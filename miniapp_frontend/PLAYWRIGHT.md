# Автоматическая проверка Mini App «Мамин помощник»

Playwright запускает настоящий браузер с **локальной** копией статического Mini App. Тесты работают с синтетическими записями, полностью подменяют API `/api/miniapp/*`, а внешние запросы блокируют. Никакие Telegram/MAX токены, персональные данные, платёжные API или production-база не используются.

## Что проверяется

- Пять основных разделов (Главная, Помощник, Трекеры, История, Профиль).
- Прямые ссылки на внутренние разделы и восстановление экрана после перезагрузки.
- Дневник малыша: сохранение записи и повторное чтение после перезагрузки.
- Сон: «Уснул» → «Проснулся», два события в истории.
- Питание: проверка пустых полей, передача времени и стороны кормления.
- Самочувствие: пустое поле не отправляется; тестовая запись сохраняется.
- Рост и вес: обязательные поля, числовой формат, запись в историю.
- Имитация Telegram/MAX SDK: заголовки и действие «Назад».
- Ошибки сервера 401/500: экран без авторизации и повтор запроса.
- Отсутствие случайных внешних запросов, платежей и реальных сообщений.

Тестовый набор выполняется в **mobile Chromium (Android-профиль)** и **mobile WebKit (iPhone-профиль)**. Это эмуляция браузера, а не тест настоящего Telegram или MAX на телефоне.

## Запуск разработчиком

В каталоге `miniapp_frontend/`:

```bash
npm ci
npx playwright install --with-deps --only-shell chromium webkit
npm run test:e2e
```

## Автоматизация GitHub

Workflow: `.github/workflows/mama-playwright.yml`.

- Запускается на PR с изменениями Mini App и тестовой инфраструктуры.
- Запускается после публикации соответствующих изменений в `main`.
- Запускается ежедневно по расписанию в 03:17 UTC (около 06:17 по Москве; фактическое время GitHub может отличаться).
- Доступен ручной запуск через `workflow_dispatch`.
- Результат отображается прямо в GitHub Actions как PASS/FAIL.
- При ошибке прилагаются скриншот и Playwright trace (артефакты хранятся 3 дня).

## Границы

Этот набор проверяет **только поведение Mini App и клиентские запросы к синтетическому API**. Настоящую авторизацию Telegram/MAX, работу сервера и БД, реальную доставку бот-сообщений, оплату и системные разрешения смартфонов он **не** проверяет. Эти тесты требуют отдельного тестового окружения, тестовых токенов и устройств. Production в процессе не изменяется.
